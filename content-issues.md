# Content issues

Log of discrepancies between this manual and the source book, plus editorial gaps noticed while actually using the manual. Newest entries at the top. Close entries in place with a short resolution note; do not delete resolved entries.

Scope is **content only**—extractor bugs, tooling issues and repo mechanics go elsewhere (see [DEVELOPMENT.md](DEVELOPMENT.md)).

## How to file an entry

- Give it an ID `CI-NNN`, one higher than the highest existing ID (open or resolved).
- Record the date filed in ISO 8601.
- Point at the specific location in the manual (file + section, or file + table row).
- State what you observed and why it seems wrong.
- Suggest a next step. It is fine if the next step is "investigate"—you do not need to know the fix to file the entry.

When resolved, move the entry to the **Resolved** section and add a one-line resolution note with the date and what changed.

### CI-012—Focus-block hold-and-probe leaves the per-chapter working-state update procedure ambiguous

- Filed: 2026-08-28
- Location: [approach.md §7 focus-block step 6](approach.md#focus-block); [approach.md §8](approach.md#8-tracking) per-chapter working state description; [chapter-02.md](chapter-02.md) "Your first Ch. 2 session" walkthrough steps 4 and 5. Related, but not affected because it uses a hold-only session model: [chapter-01.md](chapter-01.md) session walkthroughs.
- Observed: On session 2 of Ex. 2.1, Richard started at the working-state `current bpm` of 82 (established during session 1's ceiling probe) and probed cleanly to 94 within the 15-minute focus block. The manual clearly says the log entry records the session ceiling ([§7 focus-block step 6](approach.md#focus-block)) but does not spell out how to update the working state's `current bpm` and `last pass bpm` columns after such a session. [§8](approach.md#8-tracking) hinted that the two columns can differ ("after two consecutive passes at a bpm, current bpm advances one increment while the last pass bpm still records the tempo you actually passed at") but did not turn that hint into a concrete step-by-step procedure. The reader was left choosing between an aggressive interpretation (set `current bpm` to the session ceiling; skips the two-pass confirmation) and a strict interpretation (advance `current bpm` one increment per two consecutive sessions passing the working-state starting bpm; wastes the probing data). CI-009's rewrite of the chapter-02.md walkthrough added hold-and-probe within-session behaviour without updating the working-state procedure in either place.
- Concern: Under hold-and-probe, a student who cleanly probes several rungs above the working-state current bpm in a single session has no clear rule for where the next session should start. Reading strictly, they either lose the probing data (next session starts back at the working-state current bpm, then re-climbs) or invent their own advancement policy. The working-state columns exist to answer "what bpm am I on next time?" and were not doing so for Ch. 2 in practice.
- Resolved: 2026-08-28 — [approach.md §8](approach.md#8-tracking) now spells out the update mechanic explicitly as a bulleted procedure: `last pass bpm` ← session ceiling; `current bpm` ← `min(this session's ceiling, previous session's ceiling) + one increment` (i.e. one increment past the highest bpm cleared cleanly in both this session and the previous session); first-ever session bootstraps `current bpm` to the session ceiling directly; regression at the session's starting bpm applies the [§4](approach.md#4-the-tempo-target-and-clean-pass-rule) rule instead. Under hold-only sessions the two ceilings match every session and `current bpm` advances every second session; under hold-and-probe they can diverge and `current bpm` trails the ceiling by one increment. [§7 focus-block step 6](approach.md#focus-block) split into two sub-steps (log entry + working-state update) and now references §8 for the update rule. [chapter-02.md](chapter-02.md) walkthrough steps 4 and 5 gained explicit "then update the working state per §8" lines. [chapter-01.md](chapter-01.md) session walkthroughs gained analogous update lines noting that under Ch. 1's hold-only model `current bpm` and `last pass bpm` coincide.
- Lessons: The advancement-rule text ("advance the current bpm by one increment per two consecutive passes at the current bpm") was authored for a hold-only session model and did not obviously generalise when CI-009 introduced hold-and-probe for Ch. 2. The unified rule that works for both models — "highest bpm passed in both consecutive sessions + one increment" — needs to be spelled out once in §8 rather than left implicit. Direct input to the CI-005 chapter-sheet template: template must state which within-session model applies (hold-only or hold-and-probe) and, if hold-and-probe, remind the reader that `current bpm` trails the session ceiling by one increment. Also: within-session behaviour changes (like CI-009's Stage 2+ hold-and-probe rewrite) must be checked against the tracking-format description for downstream ambiguity — the two are load-bearing on each other.
